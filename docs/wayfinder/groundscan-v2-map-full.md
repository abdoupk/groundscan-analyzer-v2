## Destination

A **decision-complete specification** for a greenfield OKM analysis engine - behaviour, contracts, and invariants - with a **frozen scientific contract** as a required sub-deliverable. The specification covers the engine *and* the epistemic regime that governs the claims the engine is allowed to make.

Reached when all seven are settled, and a competent implementer could begin with zero open design questions:

1. Coordinate doctrine resolved: what a coordinate **is**, origin, units, measured/derived/index provenance, single-scan frame, fused frame, reference scan, registration transforms, perpendicular scans, deterministic reference selection, and the field interpretation of `X = 12`, `Y = 8`, `unit = m`.
2. Latitude/longitude disposition decided.
3. Perpendicular-scan semantics decided.
4. Determinism inventory closed - every input-order, filesystem-order, iteration-order, clustering-order, reference-selection, tie, ranking, and floating-point hazard has a rule or a named rejection.
5. Scientific behaviour verdicts recorded as **preserve / redesign / remove**, per legacy scientific capability.
6. Dependency decisions made, each carrying the evaluation the brief requires.
7. Quality bar fixed: strict typing, strong linting, mutation testing, property-based testing, meaningful branch coverage, clean dependency graph, no dead code, no hidden presentation coupling - **plus the engine's own epistemic rules: what claims it may make and how limitations travel with its output.**

The destination is a specification to hand off and iterate on. It is **not** implementation, **not** an architecture, and **not** a build plan.

## Notes

**Domain.** Scientific analysis engine for OKM ground-scan (EM/GPR) data. Reads a survey of operator-acquired scan exports; emits located, characterised, bounded **detections**. No reporting, viewer, visualisation, plotting, or TUI - those may later exist as external consumers of the engine's structured results.

**Skills every session must consult.** `grilling` and `domain-modeling` (call the Skill tool for both, always). The glossary lives in `CONTEXT.md` at the repo root; keep it free of implementation detail. Vocabulary settled so far is recorded there and must not be re-litigated.

**Standing constraints - settled during charting, not open questions.**

- *One CSV contract, not a device framework.* ~~All OKM devices in scope share the same export structure.~~ **SUPERSEDED by research.** The export is a `Visualizer 3D Studio` serialisation whose columns are an *operator checklist* - every one tickable/untickable, plus configurable delimiter, decimal separator, and decimal places, with an `Apply Active Modifiers` flag that changes the scientific meaning without changing headers. The common-structure requirement survives as *the section grammar is common*; the common *column set* does not. Do not build device-specific adapters or a plugin framework - tolerated variation belongs in a documented contract. But a **positional** parser will silently mis-read real files, so the input contract must be name-based and must treat the active modifiers as a first-class fact.
- *The real input is a sectioned export*, not plain CSV: `+++ Characteristics +++`, `+++ Meta Data +++`, `+++ Soil Type +++`, `+++ Measuring Values +++`, with eight measuring columns. Treat this as the product requirement it is.
- *No geodetic science.* Latitude/longitude must not be used for georeferencing, registration, alignment, fusion, coordinate transformation, candidate positioning, validation, scoring, confidence, compass conversion, or coordinate-frame determination. No GPS, UTM, EPSG, WGS84, or geodetic transformations in the engine. (What happens to the columns themselves is an open ticket, not a settled constraint.)
- *Scope is the analysis engine only.* No reporting, report generation, viewer, visualisation, plotting, TUI. Do not preserve presentation code or presentation abstractions for a hypothetical future consumer.
- *Clean greenfield rebuild.* Do not preserve code because it existed in the legacy system. Anything with no legitimate role in the new engine is removable. No dead code kept for hypothetical future use.
- *No historical baggage.* No old version numbers, release names, milestone terminology, stale compatibility notes, old branch names, or historical implementation labels in v2 source, docstrings, comments, or current documentation. Historical material is evidence during archaeology only.
- *Units of work.* One **survey** in, one fused result out, with per-scan results as internal intermediates. Registration, reference selection, and frame reconciliation are engine concerns.
- *Depth is device-reported.* `Depth Z [m]` is carried verbatim, flagged as device-reported, and never presented as verified physical depth. No engine-derived depth from TWT or soil factors.
- *The engine gates only on physics it can defend* - missing signal, degenerate lattice, no coverage. Judgement calls about whether something is "worth reporting" are not the engine's. Otherwise the engine annotates, it does not refuse.
- *Architecture is not prescribed here.* Do not force clean architecture, hexagonal, DDD, services/repositories, or any particular folder or package layout. Derive the simplest structure that correctly supports the decided behaviour. Prescribing it is out of scope for this map; it is an **output** of the map, not a decision on it.
- *Preserved vocabulary.* scan, survey, lattice, response, anomaly, **detection** (not "finding", not "candidate"), characterisation, limitation. Retired as domain nouns: candidate, fused candidate, fragment, conflict candidate, gate, evidence, score.

**Two hard facts that shape every coordinate decision.**

- There is no site or global datum anywhere in the legacy system. Every scan's metric columns start at `0.0000` on both axes. Multi-scan work never built a shared origin: candidates were normalised into `[0,1]^2` against the *reference scan's own extent*, then affinely re-expanded. So legacy had no physical site frame to lose - and no frame to inherit.
- The 90-degree case is a genuine ambiguity, not a missing feature. Registration searched 8 rigid transforms (4 rotations + 4 reflections) x a 13x13 integer shift window, and **no adapter ever set scan orientation** - it was only ever guessed from filenames containing `h`/`horizontal` or `v`/`vertical`. On a rectangle, `rot90` and `flip_rot90` are indistinguishable from the map alone.

**Legacy evidence lives at `docs/legacy/`** (untracked). It is archaeology: read it, cite it, do not import, copy, or adapt it. It stays until the v2 oracle and regression harness replaces it, then it is deleted. Relevant subtrees: `groundscan/` (engine), `groundscan_research/` (33 diagnostic modules, never imported by the engine), `validation/` (oracles, calibration tables, frozen hashes), `tests/` (62 files, 810 test functions), `scans/vendor_demo/` (9 real OKM exports).

**An honest limit on this map.** There is no independent field ground truth. Not one, anywhere. The vendor corpus is vendor *educational* material, and its own manifest says so. Consequently "preserve" can only ever mean *preserve the discipline*, never *preserve accuracy* - and no output of this engine may be described as field-validated. The engine's epistemic regime ticket carries this as a hard constraint.

- [What an OKM device actually measures, and what its documentation says](https://github.com/abdoupk/groundscan-analyzer-v2/issues/20): the export is `Visualizer 3D Studio` software output, not a device export - every column but `Scan Value` is computed from operator-typed metadata. `Scan Value` is unitless, signed, and not comparable across scans, with OKM's own 131,000-scale example labelled *"amplitudes are very low / no relevant signals"* - the regime all nine files live in, which vindicates ratios-only use and forbids an absolute threshold. `L/(n-1)` confirmed from two official artifacts, axis inclusive of both ends. `Scan Mode` is provably inert, so the raster is raw accumulation order and zigzag correction was doing real work. **Orientation does not exist in the format in any OKM version** - the operator is told to mark their start point on the ground.
- [Published methods for interpreting OKM and shallow ground-scan responses](https://github.com/abdoupk/groundscan-analyzer-v2/issues/21): the literature forces one reframe - **classify the anomaly, never the object** (Persico et al. 2024: *"there is no mathematical method that can verify a detected target as a cavity"*). Four legacy claims are unsupported: `cavity-like`, `geological-like` as a physical class, `dipolar-response` as a peer class (Lenz's law makes a +/- lobe pair a *consequence* of metal, and cavities do it too), and 3-sigma as a significance level. PAS 128 puts single-technique depth accuracy at +/-40% of depth; the "verbatim depth" decision is upheld **but only if verbatim means explicitly attributed**. Existence-confidence and positional-accuracy must be separate output fields. Also: a zig-zag grid is a *clustered* dataset, and exact interpolators manufacture anomalies that were never measured.
- [Prior art and reusable tooling for ground-scan processing](https://github.com/abdoupk/groundscan-analyzer-v2/issues/22): `orjson` is **disqualifying** for the frozen contract - it silently writes `null` for NaN/Inf and will not read them back. `pydantic` beats `jsonschema` decisively, because `jsonschema` ships no `py.typed` and would force `Any` into `src/`. Drop `natsort` (unreleased since 2023). `scipy` already covers ~80% of the hand-rolled numeric work. Pint models the grid frame correctly, and OKM's own docs independently confirm the grid has no metres in it. `audit-requirements.txt` is stale and `AGENTS.md`'s "in sync" claim is wrong.
- [What is a coordinate?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/2): **nothing in an OKM export is a measured coordinate** - every column but the signal is computed by export software from operator-typed metadata, so the legacy `measured` provenance was false. A detection's canonical position is the **lattice index** - two integers, no units - because it is the only spatial fact that survives an operator who typed nothing, and OKM's own export dialog already leads with `Scan Field Position (Index)`. A field position is a derived rendering against the operator's assertion, carried and labelled `operator-asserted`, and **absent - stated as absent - when no extent was declared**. Provenance is exactly three values, **per axis**: `device-index`, `operator-asserted`, `engine-constructed`; the word *measured* is retired from the vocabulary. A position cannot exist without its frame, and neither can any derived quantity, so a bare `x: float` is a type error. The field case resolves: `X = 12, Y = 8, unit = m` is 12 m along and 8 m across from the operator's start point, in metres that operator typed - not East 12 / North 8, and no conversion to a location on Earth is offered.
- [What may the engine claim?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/3): **the engine describes the anomaly, never the object** - a material tier on a single scalar channel with no phase information and no field truth would be unfalsifiable, so `metallic-like`, `cavity-like` and `tunnel-like` are **consumer vocabulary** and may never appear in the engine's contract, hedged or not. Characterisation is permitted **only** as a compatibility statement naming an explicit defensible source, and with no such source the engine emits measurements and no characterisation. **Every claim carries its warrant inline**; a naked confidence score is invalid because the reader cannot tell what it is confidence *of*, and warrants never combine - existence-confidence and positional-accuracy are different claims and are never aggregated. **Limitations are first-class, claim-specific, machine-readable, present when empty**, and a limitation that is no longer true must fail a test. **Weak is not undefendable**: a faint detection is emitted with its limitations attached, and thresholds being policy, **there is no quality bar inside the engine at all**. The strongest claim available: *an anomaly at impulse 34, line 12, extent 3 by 5 impulses, bipolar response, consistent with a family previously associated with metallic targets*.
- [What is depth, given the provenance vocabulary does not cover it?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/24): measured across all nine real exports, `Depth Z [m]` is **per-sample and noisy** - adjacent samples differ by ~14% of a line's entire depth spread - and its correlation to response **flips sign between files** (-0.967 in Error Signal, +0.722 in Pipeline, ~0.00 in three others). So the file supplies **no depth per anomaly**, and any point value would be an invented aggregation. Depth is a **measurement property, not part of the position**; its provenance is a **fourth value**, `derived-by-vendor-software-from-operator-assertion`, because reusing `operator-asserted` would imply the operator stated a depth when they stated a soil type. A detection's depth is an **interval over its covered samples, never a point**; absent depth is stated absent, never zero, and never suppresses the detection. **No PAS 128 band is borrowed** and **no TWT or soil-factor depth is derived** - the legacy's 547-line `soil/experimental.py` is cut.

- [What frame do fused detections live in, and what is the reference scan?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/9): the reference is a **frame convention, not an assertion** - chosen by a **total order over a hash of the canonicalised measurement payload**, recorded `engine-constructed`, reading nothing an operator declared. Selecting the most central or most consistent scan was rejected because it makes the engine **rank operator assertions**, and with two conflicting declarations it would silently discard one. Canonicalisation excludes metadata, filenames, ordering and declarations, so a cosmetic edit cannot re-frame a survey whose data is identical; a human-readable label may be shown but never participates. **Re-rooting preserves the physical result, not the numbers** - same detections, same per-scan results, same declared relationships - and across a 90-degree relation the tuple is legitimately re-expressed, so invariance is never of the index tuple. **Each connected component of the orientation graph is rooted independently**; a missing link blocks only its own component, preserving the orientation ticket's per-pair withholding rather than tightening to full connectivity. **Contradictory assertions are reported and the affected fused position withheld** - the engine has no authority to adjudicate, so it produces the contradiction rather than a position built on one horn of it. ...

Auditing the only labelled corpus showed it meets neither: all nine cases carry provenance: vendor-metadata-notes, the manifest declares independent_field_ground_truth: false, and the keys excavated, confirmed, erified, coordinates and depth_m are **absent entirely**. **Eight of nine cases assert only pattern presence or count** in vocabulary the claim regime has since forbidden, so they assert nothing that survives; **the single independent fact in the corpus is a negative** (Error Signal carries 	arget_present: false). No source is built in this effort - **the bar is documented, not satisfied**, and the record must not imply otherwise. **Characterisation is deferred, not refused**: the record keeps an optional field, empty and explicitly unlicensed, so a future source can populate it without redesign. ...
- [Detection core: background, scale, threshold, connectivity](https://github.com/abdoupk/groundscan-analyzer-v2/issues/11): **redesign, and the engine has no threshold at all.** It emits a **residual field and a deterministic component hierarchy**; membership, size, polarity and response are derived at a level the **consumer** selects, because thresholds are policy and policy is not the engine's to apply. Background is a **multiscale median model** with its computational conventions recorded as **processing metadata - describing the computation, not claiming anything about the ground** - because a single fitted plane leaves trend exceeding residual spread in **6 of 9 real files**. Robust scale is **tiered with two estimators of different failure modes**, and on disagreement the engine emits raw residuals plus both estimates with `scale_disagreement` rather than a scale-normalised view; the final pair and tolerance are **deferred to measurement**. ...
- [Shape and geometry descriptors](https://github.com/abdoupk/groundscan-analyzer-v2/issues/12): **only two descriptors are preserved, both index-space and both pitch-free** - `solidity = A / convex-hull area` (hull of **cell corners**, exactly 1.0 for any convex set) and `compactness = 4*pi*A / P^2` (`P` = exposed lattice-edge perimeter **including hole boundaries**). Both are ratios, hence computable even when no extent was declared, which is the normal case. Connectivity is **fixed in the contract, not exposed**. **PCA orientation, extents and elongation are removed** from the current contract because they require pitch - orientation being exactly what the claim regime already restricted. Two convention errors were found and fixed while measuring: a cell-area numerator paired with a centre-based hull scored a solid block at 4.0, and an erosion-based perimeter scored a domino above the isoperimetric bound - both caught by a sanity check, which is the argument for keeping the exact-hull oracle. Compactness's **size-dependence is a precondition**: a 50-cell line scores 0.06 where a 5x5 block scores 0.79, both perfectly convex, so equal solidity does not imply equal compactness. Descriptors are computed **only at a level the consumer explicitly selects**, recorded with the recipe, with no transferable default, and rejected when the robust scale disagrees. The legacy "one metric, two thresholds" ambiguity **dissolves by construction**. ...
- [Characterisation: what a detection is made of](https://github.com/abdoupk/groundscan-analyzer-v2/issues/13): **the engine computes no characterisation**; the field is **reserved** - present in contract and schema, empty, always - which means future-compatible contract space, so **deleting it would be a contract regression, not a cleanup**. What is emitted instead is **measurement-side evidence on condition**, never silently dropped: polarity / solidity / compactness need a selected level; **dominance** additionally needs >=2 components; recurrence needs a declared orientation, shared frame, tolerance, chance baseline and correspondence rule; **stability** is an attribute of the **scan** (perturbation kind, magnitude, reference, method, seed, trials), deterministic per seed and **not validity**. Absent evidence yields `not-emitted: requires <X>` as a first-class state. **Dominance** is the peak-magnitude ratio of the two strongest components - measured **13 stable / 0 drifting / 0 unstable**, worst deviation 0.0101, so it ships as a structurally stable ratio, with its separate count-dependent *existence* condition reported alongside. Measured principle for classifying any derived quantity: **partition, ratio, or count** predicts its stability class - polarity is exact by disjointness, ratios are exact per-component, counts drift 0-8 components at a fixed level. **Two scans of one area have different robust scale** (3.87 vs 2.97), so a level is never shared between scans. ...
- [What does "deterministic" mean as an observable contract?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/6): **two guarantees, distinct in kind** - **repeatability** (same input, same environment, same bytes; measured achievable, 9/9 files byte-identical over repeated runs) and **order-invariance** (the same set of scans in any order gives the same survey result). **Platform invariance is explicitly declined**, since float conventions in filtering, linear algebra and the convex hull bound it and it cannot be demonstrated; cross-platform figures may be reported informationally but are not a guarantee. Order-invariance comes from **canonical ordering by the canonical payload hash before any order-sensitive reduction, applied to every unordered collection and every intermediate stage** whose result can depend on iteration order - **the same mechanism that makes the canonical reference order-free, used once rather than twice**. **Row order within a scan is contractually immaterial** (the scan is reconstructed from lattice coordinates, and the residual was measured to be a pure function of the file bytes) - stated as a contract property so a future contributor cannot break it silently - and **duplicate coordinates with conflicting values are an input-contract error**. ...
- [The vocabulary lint: what is banned, where, and how it fails](https://github.com/abdoupk/groundscan-analyzer-v2/issues/26): **two layers**, because each catches what the other misses - a **mechanical vocabulary rule** over known forbidden terms, plus a **reviewed semantic category** catching synonyms and new wording that still make a material, object or ground-class claim. Measured justification: a ban list alone passes `metallic-like` -> `metal-like`, `cavity-like` -> `hollow-like`, `tunnel-like` -> `linear-response`, `validated` -> `confirmed`, `field-validated` -> `ground-truthed`, `dipolar-response` -> `two-lobe` - **none caught by a word list**. Scope is **`src/` and `tests/` only**: measured **0 hits** across the shipped contract surface, **409** in `docs/research/` and **2,339 in 141 files** in `docs/legacy/`, because those record the forbidden vocabulary as archaeology - so a whole-repo lint would be silenced to enforce nothing. **Hard gate with reasoned per-line suppression**, following the repo's existing `ruff select = [ALL]` and `# gremlin: pardon[reason]` precedents: a lint with no escape hatch gets commented out, one with a *reasoned* escape hatch gets used because writing the reason forces the author to think. ...
- [The detection record](https://github.com/abdoupk/groundscan-analyzer-v2/issues/17): **five categories across three granularities** - **run context** (environment fingerprint, execution metadata), **scan context** (canonical payload hash, background model and conventions, scale status including disagreement, scan-level stability), **frame context** (canonical reference, declared orientations, component membership, contradictions), **detection evidence**, and **interpretive claims**. A detection belongs to a **frame, not a scan**, because a frame may span scans and a single scan uses an implicit engine-constructed local frame - forced by per-component rooting, since independently rooted components cannot nest inside one scan. Stable identifiers define the relationships and **the contract does not mandate a serialization form**. **Evidence and claims are different kinds**: evidence carries method and provenance and needs no licence; a **claim** carries value + warrant + limitation and **a claim without its warrant is unrepresentable**. `not-emitted` and `indeterminate` are **discriminated result states on both kinds**, not warrants, each with a reason code and required-evidence information - one mechanism, because expressing "solidity absent" differently from "depth absent" would itself be a contract defect. **Depth is evidence only**, never an engine depth claim. ...
- [The separation margin and stability criteria](https://github.com/abdoupk/groundscan-analyzer-v2/issues/28): **the protocol is fixed and reproducible**, and **margin, correlation, argmax stability and margin drift are reported independently with no composite score** - candidate ordering inside registration is required to compute the argmax and is **not** a ranking. Three **separate, decidable** checks produce `indeterminate`: non-unique argmax, a tie within the recorded floating-point bound, and instability under the recorded perturbation protocol - each references a *recorded protocol* rather than a fixed constant, so the perturbation magnitude is a **live parameter**; a passing check means the candidate is **well-defined and stable under that protocol, never that the alignment is physically real**. **There is no hidden margin threshold and no final separation threshold** until an adequate corpus including independent real repeat acquisitions exists. ...
- [The order-dependence inventory and its tie rules](https://github.com/abdoupk/groundscan-analyzer-v2/issues/15): **four hazard classes**, each with a rule, and **the taxonomy is fixed for this phase but explicitly reopenable** - v2 is unbuilt, so a hazard that cannot be represented correctly reopens the taxonomy rather than being forced into a class that does not fit. **Order** is closed by canonical ordering plus lattice-order numbering, with **padding excluded from component identity entirely** so that moving or adding padding cannot renumber anything - a padded cell has no measurement, so letting it hold a position would make identity depend on file format rather than the ground. **Tie** is decided by three checks, plus **an exact dominance tie is `indeterminate`** (measured constructible from a real input: duplicating a row of `Tunnel - Original` gives an **exact** 18.0 == 18.0 peak tie, and canonical ordering must not manufacture a winner), plus **an exact scale-estimator tie recorded in `scale_status`** (measured: on `[0,1,1,1,1]` MAD and IQR both give exactly 0.0, and a tie is **neither agreement nor disagreement** so it must never silently trigger a fallback). The depth interval is **order-free by construction** - `nanmin`/`nanmax` exclude NaN, so an all-NaN set yields empty rather than a silent zero.
- [The perpendicular survey: a 90-degree turn, two scans, one answer](https://github.com/abdoupk/groundscan-analyzer-v2/issues/10): **the result is a frame relation, not a fusion** - no measurement cells are merged or resampled, and **no cross-scan count or density is ever produced**, counts staying per-scan even over an overlap; the forbidding mechanism is already in the vocabulary, since **an interpolated value is padding by definition** so a merged grid would not be a measurement grid and every count over it would count inventions. The relation is carried as **composed classes in Z/4** (Same=0, 90cw=1, Opposite=2, 90ccw=3) walked from the canonical reference, so two scans' classes **difference** to their pairwise relation and a cycle is either closed or contradictory, never merely implausible - the declared word is the assertion, the composed class is `engine-constructed`, **no rotation is applied at the last moment** and no transform matrix is ever an assertion; reflections are outside the vocabulary and a declaration is never repaired into its own mirror. The **canonical position is the exact integer lattice index**; a shared-frame position is **derived**, retains its scan-local origin, records **per-axis provenance**, may be **fractional** when participating scans declared different pitches, and is then **not a homogeneous unit pair** - so re-rooting does not merely re-express numbers, it **changes the unit along each axis**. ...
- [The input contract: a name-based reading of a user-configurable export](https://github.com/abdoupk/groundscan-analyzer-v2/issues/23): the contract is a **closed column registry matched by name**, never by position - each row carries a normalised name, a **role** and a **field provenance**, and normalisation is exactly *trim whitespace + case-insensitive*, so **the unit is part of the name** (`Impulse X [ft]` is an unknown column, never a convertible variant) and **no alias table exists** until OKM shows a real one. **Reordering is not a variation at all** - a file cannot carry column order as information, so the silent-mis-read hazard is impossible rather than handled. Required roles are exactly `response`, `impulse`, `scan-line`; every other field is optional and its absence is recorded, never fatal. **The metric columns are a derived echo nobody had checked** - measured `Iron Box` (3.00 m over 19 impulses) runs 0.0000 to 3.0000 in 0.1667 steps, exactly `L/(n-1)` - so the engine **recomputes the expected series** under the named versioned convention `metric-coordinate-v1`, compares at a **tolerance derived from the declared decimal precision** (four places gives 0.00005, recorded with the check), and **never replaces the vendor values**. This makes the all-zero trap **decidable**: all-zero metrics with no resolvable extent is **not a contradiction** (the documented formula multiplied a zero), all-zero metrics against a declared non-zero extent **is** one. ...
- [What happens to latitude and longitude?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/5): **registered, but only the presence state is kept** - absent, present-but-empty, present-with-value - and the **values are discarded** from both the carried record and the canonical payload. The deciding fact is that the export **declares no datum at all**, so by the glossary's own rule these are **unframed values**: numbers wearing a position's grammar, which the engine may retain the state of but never the content of. Measured: the pair is an **optional group applied at scan-field level, not per point** (the dialog asks for *"the GPS Latitude of your scan area to mark its position for Google Maps"*), the common state is unattached with OKM's own panel showing `N/A`, and OKM's stated purpose is **relocation and documentation** - never orientation or registration. All nine files carry the columns **present-but-empty** (``,``, zero-length, not `0.0000`). Discarding the value is also what keeps [What frame do fused detections live in?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/9)'s canonicalisation ruling intact, since metadata is excluded by design and carrying the value would need a fresh exception to a decision made on principle. ...
- [Which quality signals are defensible physics, and which are policy?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/7): the ruling is a **rule, not a case-by-case judgement** - *a threshold is retained only if it is required by the definition or computability of a **named quantity**; if removing it merely changes whether a result is acceptable, ready, safe, strong or weak, it is consumer policy and is deleted.* Applied across legacy's 13 field-quality thresholds, 15 operational thresholds, 7 screening values and **four weight dictionaries**, it removes every policy number and keeps every real quantity, because legacy was not gating on judgements - it was **measuring real quantities and hanging policy numbers on them**. **Two refusals exist and physics has none**: a scan is refused only for a contract violation ([#23](https://github.com/abdoupk/groundscan-analyzer-v2/issues/23)'s closed reasons), and a contract-valid scan is **always read** however underdetermined the physics - only the affected output is withheld as `not-emitted`. That inverts legacy, where `hard_block` on a quality tier stopped extraction outright and a judgement masqueraded as an input failure. **`not-emitted` now means undefined, not insufficient**: it applies only where a quantity is mathematically undefined or incomputable, and names which computation; a thin sample is **emitted with its sample size as an explicit fact** and sufficiency is the consumer's. ...

The capability is recorded as deferred rather than discarded, but the question of whether a shape axis expressible purely in index space (a lattice angle, not a physical angle) is worth emitting is not yet sharp enough to ticket - it needs a consumer's view of what a lattice angle would be *for*.

- **Whether the validation apparatus is rebuilt in this effort or a following one.** The epistemic regime is decided here; the size of the apparatus that enforces it is not. The regime does, however, fix two things that apparatus must do: enforce a **banned-claim-form check** so no `metallic-like` or field-validated phrasing can enter the contract, and enforce the **stale-limitation test**. The record ruling adds a third that is mechanical rather than procedural: the **closed vocabulary** must hold across fields, enums, limitation strings, and error messages. [The metamorphic properties](https://github.com/abdoupk/groundscan-analyzer-v2/issues/30) add two more, and the second is the one that would be missed: the **closed transform vocabulary** must be enforced alongside the closed claim vocabulary, and a property whose **preconditions no longer hold must fail** - structurally identical to the stale-limitation test, applied to promises rather than to claims. [The vendor compatibility gate](https://github.com/abdoupk/groundscan-analyzer-v2/issues/18) adds a fourth: **each definitional bound needs an independent validation test** - bound validity, witness attainment, production agreement - with an oracle **independent of the implementation**, since one sharing production's code verifies nothing. Still fog: a handoff boundary, not a design question.
- **An adequate evaluation corpus for the separation criterion.** Named now as a named gap rather than a fog patch, because it is the single thing standing between a provisional criterion and a real one. It requires **independent real repeat acquisitions** - two operators or two passes over genuinely the same ground, with no relationship known in advance. The corpus has none: the nine files are separate vendor demo scans, and the one genuine pair correlates at 0.7678 where constructed repeats reach 0.9998, so it cannot stand in. Until such data exists, `indeterminate: criteria-not-established` remains correct for close cases and the separation criterion stays provisional.
- **Cross-acquisition stability validation.** Self-alignment stability is measured; whether the argmax check is valid when aligning two *independent* acquisitions of one area is not. Same underlying cause as the corpus gap above - the same missing real repeat data would settle both.
- **Whether a stable reference is a defensible *response* claim** - a recurring claim about the measurement rather than the ground, and a possible answer to a product with no field truth. Named in the characterisation licensing ticket; sharp enough to be a ticket only once that ticket establishes whether a defensible source is reachable at all.

## Destination

A **decision-complete specification** for a greenfield OKM analysis engine - behaviour, contracts, and invariants - with a **frozen scientific contract** as a required sub-deliverable. The specification covers the engine *and* the epistemic regime that governs the claims the engine is allowed to make.

Reached when all seven are settled, and a competent implementer could begin with zero open design questions:

1. Coordinate doctrine resolved: what a coordinate **is**, origin, units, measured/derived/index provenance, single-scan frame, fused frame, reference scan, registration transforms, perpendicular scans, deterministic reference selection, and the field interpretation of `X = 12`, `Y = 8`, `unit = m`.
2. Latitude/longitude disposition decided.
3. Perpendicular-scan semantics decided.
4. Determinism inventory closed - every input-order, filesystem-order, iteration-order, clustering-order, reference-selection, tie, ranking, and floating-point hazard has a rule or a named rejection.

## Notes

**Domain.** Scientific analysis engine for OKM ground-scan (EM/GPR) data. Reads a survey of operator-acquired scan exports; emits located, characterised, bounded **detections**. No reporting, viewer, visualisation, plotting, or TUI - those may later exist as external consumers of the engine's structured results.

**Skills every session must consult.** `grilling` and `domain-modeling` (call the Skill tool for both, always). The glossary lives in `CONTEXT.md` at the repo root; keep it free of implementation detail. Vocabulary settled so far is recorded there and must not be re-litigated.

**Standing constraints - settled during charting, not open questions.**

- *One CSV contract, not a device framework.* ~~All OKM devices in scope share the same export structure.~~ **SUPERSEDED by research.** The export is a `Visualizer 3D Studio` serialisation whose columns are an *operator checklist* - every one tickable/untickable, plus configurable delimiter, decimal separator, and decimal places, with an `Apply Active Modifiers` flag that changes the scientific meaning without changing headers. The common-structure requirement survives as *the section grammar is common*; the common *column set* does not. Do not build device-specific adapters or a plugin framework - tolerated variation belongs in a documented contract. But a **positional** parser will silently mis-read real files, so the input contract must be name-based and must treat the active modifiers as a first-class fact.
- *The real input is a sectioned export*, not plain CSV: `+++ Characteristics +++`, `+++ Meta Data +++`, `+++ Soil Type +++`, `+++ Measuring Values +++`, with eight measuring columns. Treat this as the product requirement it is.
- *No geodetic science.* Latitude/longitude must not be used for georeferencing, registration, alignment, fusion, coordinate transformation, candidate positioning, validation, scoring, confidence, compass conversion, or coordinate-frame determination. No GPS, UTM, EPSG, WGS84, or geodetic transformations in the engine. (What happens to the columns themselves is an open ticket, not a settled constraint.)
- *Scope is the analysis engine only.* No reporting, report generation, viewer, visualisation, plotting, TUI. Do not preserve presentation code or presentation abstractions for a hypothetical future consumer.
- *Clean greenfield rebuild.* Do not preserve code because it existed in the legacy system. Anything with no legitimate role in the new engine is removable. No dead code kept for hypothetical future use.
- *No historical baggage.* No old version numbers, release names, milestone terminology, stale compatibility notes, old branch names, or historical implementation labels in v2 source, docstrings, comments, or current documentation. Historical material is evidence during archaeology only.
- *Units of work.* One **survey** in, one fused result out, with per-scan results as internal intermediates. Registration, reference selection, and frame reconciliation are engine concerns.
- *Depth is device-reported.* `Depth Z [m]` is carried verbatim, flagged as device-reported, and never presented as verified physical depth. No engine-derived depth from TWT or soil factors.
- *The engine gates only on physics it can defend* - missing signal, degenerate lattice, no coverage. Judgement calls about whether something is "worth reporting" are not the engine's. Otherwise the engine annotates, it does not refuse.
- *Architecture is not prescribed here.* Do not force clean architecture, hexagonal, DDD, services/repositories, or any particular folder or package layout. Derive the simplest structure that correctly supports the decided behaviour. Prescribing it is out of scope for this map; it is an **output** of the map, not a decision on it.
- *Preserved vocabulary.* scan, survey, lattice, response, anomaly, **detection** (not "finding", not "candidate"), characterisation, limitation. Retired as domain nouns: candidate, fused candidate, fragment, conflict candidate, gate, evidence, score.

**Two hard facts that shape every coordinate decision.**

- There is no site or global datum anywhere in the legacy system. Every scan's metric columns start at `0.0000` on both axes. Multi-scan work never built a shared origin: candidates were normalised into `[0,1]^2` against the *reference scan's own extent*, then affinely re-expanded. So legacy had no physical site frame to lose - and no frame to inherit.
- The 90-degree case is a genuine ambiguity, not a missing feature. Registration searched 8 rigid transforms (4 rotations + 4 reflections) x a 13x13 integer shift window, and **no adapter ever set scan orientation** - it was only ever guessed from filenames containing `h`/`horizontal` or `v`/`vertical`. On a rectangle, `rot90` and `flip_rot90` are indistinguishable from the map alone.

**Every corpus-derived number is registered at `docs/measurements.md`** with its **standing** - one entry per figure, quoted from there and never restated. Four values, closed vocabulary: `recorded` (quote as a point), `swept` (quote as the sweep's interval, never a point), `unpinned` (**not evidence**), `unrecoverable` (**retired**). The spread never decides anything - it *is* the interval - so there is no threshold in it. The rule **binds the ticket that declares staleness**: [Detection core](https://github.com/abdoupk/groundscan-analyzer-v2/issues/11) marked figures stale and was then audited for reusing one. Enforcement is **procedural, not mechanical** - a lint cannot work, because a literal search for one withdrawn figure misses another written with different glyphs. A ticket that quotes a figure should carry its standing with it.

**Legacy evidence lives at `docs/legacy/`** (untracked). It is archaeology: read it, cite it, do not import, copy, or adapt it. It stays until the v2 oracle and regression harness replaces it, then it is deleted. Relevant subtrees: `groundscan/` (engine), `groundscan_research/` (33 diagnostic modules, never imported by the engine), `validation/` (oracles, calibration tables, frozen hashes), `tests/` (62 files, 810 test functions), `scans/vendor_demo/` (9 real OKM exports).

**An honest limit on this map.** There is no independent field ground truth. Not one, anywhere. The vendor corpus is vendor *educational* material, and its own manifest says so. Consequently "preserve" can only ever mean *preserve the discipline*, never *preserve accuracy* - and no output of this engine may be described as field-validated. The engine's epistemic regime ticket carries this as a hard constraint.

- [What an OKM device actually measures, and what its documentation says](https://github.com/abdoupk/groundscan-analyzer-v2/issues/20): the export is **`Visualizer 3D Studio` software output, not a device export** - every column but `Scan Value` is computed from operator-typed metadata. `Scan Value` is unitless and **not comparable across scans**, and OKM's own 131,000-scale example is labelled *"amplitudes are very low / no relevant signals"* - the regime all nine files live in, which vindicates ratios-only use and forbids an absolute threshold. `L/(n-1)` confirmed from two official artifacts. `Scan Mode` is **provably inert**. **Orientation does not exist in the format in any OKM version.**

- [Published methods for interpreting OKM and shallow ground-scan responses](https://github.com/abdoupk/groundscan-analyzer-v2/issues/21): **classify the anomaly, never the object** (Persico et al. 2024: *"there is no mathematical method that can verify a detected target as a cavity"*). Four legacy claims are unsupported - `cavity-like`, `geological-like` as a physical class, `dipolar-response` as a peer class, and 3-sigma as a significance level. PAS 128 puts single-technique depth accuracy at **+/-40% of depth**, so verbatim depth is upheld **only if explicitly attributed**. Existence-confidence and positional-accuracy stay **separate fields**. A zig-zag grid is a *clustered* dataset, and exact interpolators manufacture anomalies that were never measured.

- [Prior art and reusable tooling for ground-scan processing](https://github.com/abdoupk/groundscan-analyzer-v2/issues/22): `orjson` is **disqualifying** for the frozen contract - it silently writes `null` for NaN/Inf and will not read them back. `pydantic` beats `jsonschema`, because `jsonschema` ships no `py.typed` and would force `Any` into `src/`. `natsort` dropped. `scipy` already covers ~80% of the hand-rolled numeric work. **`audit-requirements.txt` is stale and `AGENTS.md`'s "in sync" claim is false.**

- [What is a coordinate?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/2): **nothing in an OKM export is a measured coordinate.** A detection's canonical position is the **lattice index** - two integers, no units - the only spatial fact surviving an operator who typed nothing. A field position is derived, labelled `operator-asserted`, and **stated absent** when no extent was declared. Provenance is exactly three values **per axis**; the word *measured* is **retired**. A position cannot exist without its frame, so **a bare `x: float` is a type error**. `X = 12, Y = 8, unit = m` resolves to 12 m along and 8 m across from the operator's mark - not East 12 / North 8.

- [What may the engine claim?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/3): **the engine describes the anomaly, never the object** - a material tier on a single scalar channel with no phase and no field truth would be unfalsifiable, so `metallic-like`, `cavity-like` and `tunnel-like` are **consumer vocabulary** and may never appear in the contract, hedged or not. Characterisation is permitted **only** naming an explicit defensible source. **Every claim carries its warrant inline**; warrants never combine. **Limitations are first-class, claim-specific, and present when empty.** **Weak is not undefendable**, and thresholds being policy, **there is no quality bar inside the engine at all**.

- [What is depth, given the provenance vocabulary does not cover it?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/24): `Depth Z [m]` is **per-sample and noisy** and its correlation to response **flips sign between files** (-0.967 in Error Signal, +0.722 in Pipeline), so the file supplies **no depth per anomaly** and any point value would be invented. Depth is a **measurement property, not part of the position**, with a **fourth provenance value**. A detection's depth is an **interval over its covered samples, never a point**; absent depth is stated absent and never suppresses. **No PAS 128 band borrowed, no TWT or soil-factor depth derived** - the legacy's 547-line module is cut.

- [How does the engine learn the orientation of a scan?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/4): orientation is **absent from the export in every OKM version** - no column, no device, no firmware - and OKM's only guidance is verbal (*"place a little marking on the ground"*). **Optional, operator-declared, never inferred**; filename inference is rejected as a naked claim, and it is exactly what legacy did - a guess matching **none** of the nine real filenames, so registration silently searched reflections on every real file.

- [What frame do fused detections live in, and what is the reference scan?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/9): the reference is a **frame convention, not an assertion** - a **total order over a hash of the canonicalised measurement payload**, reading nothing an operator declared. Choosing the most central scan is rejected because it makes the engine **rank operator assertions**. **Re-rooting preserves the physical result, not the numbers.** Each connected component is **rooted independently**, so a missing link blocks only its own component. **Contradictory assertions are reported and the affected fused position withheld** - the engine has no authority to adjudicate.

- [What would license a characterisation, and could such a source be built?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/25): the **licensing bar** is that a source state its **method**, its **independence from the instrument vendor**, and the **conditions under which it is known to fail**. The only labelled corpus meets none of it: `independent_field_ground_truth: false`, and **eight of nine cases assert only banned vocabulary**, so they assert nothing that survives; the single independent fact is a **negative**. No source is built - **the bar is documented, not satisfied**. **Deferred, not refused**: the field stays reserved and empty.

- [Detection core: background, scale, threshold, connectivity](https://github.com/abdoupk/groundscan-analyzer-v2/issues/11): **redesign, and the engine has no threshold at all** - it emits a **residual field and a deterministic component hierarchy**, and everything else is derived **at a level the consumer selects**. Background is a **multiscale median model** whose conventions are **processing metadata, not claims about the ground**, because a fitted plane leaves trend exceeding residual spread in **6 of 9 real files** *(unpinned per the measurement register - it is residual-dependent under a window this project never pinned, and the trend term is now rejected on the claim boundary alone)*. Robust scale is **tiered with two estimators of different failure modes**; on disagreement the engine emits raw residuals and both estimates and **no** scale-normalised view.

- [Shape and geometry descriptors](https://github.com/abdoupk/groundscan-analyzer-v2/issues/12): **only two descriptors are preserved**, both index-space and pitch-free - `solidity` (hull of **cell corners**, exactly 1.0 for any convex set) and `compactness` (perimeter **including hole boundaries**). Both are ratios, hence computable when no extent was declared, which is the normal case. **PCA orientation, extents and elongation are removed** for requiring pitch. Compactness is **size-dependent**, so equal solidity does not imply equal compactness. Connectivity is **fixed in the contract, not exposed**.

- [Characterisation: what a detection is made of](https://github.com/abdoupk/groundscan-analyzer-v2/issues/13): **the engine computes no characterisation**; the field is **reserved** - present, empty, always - so deleting it would be a **contract regression, not a cleanup**. Measurement-side evidence is emitted **on condition**, never silently dropped, and absent evidence is `not-emitted: requires <X>`. **Dominance** is the peak-magnitude ratio, measured **13 stable / 0 drifting / 0 unstable** *(unpinned per the measurement register; the structural stability rests on being a ratio over a thresholded set, never on this table)*, with its count-dependent existence condition reported alongside. **Stability** is a **scan-level** attribute and is **not validity**. The classifying principle: **partition, ratio, or count predicts the stability class**.

- [What does "deterministic" mean as an observable contract?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/6): **two guarantees, distinct in kind** - **repeatability** (measured achievable, 9/9 files byte-identical over repeated runs) and **order-invariance**. **Platform invariance is explicitly declined**, since float conventions in filtering, linear algebra and the convex hull bound it and it cannot be demonstrated. Order-invariance comes from **canonical ordering before any order-sensitive reduction** - the same mechanism that makes the reference order-free, used once rather than twice. **Row order within a scan is contractually immaterial**; duplicate conflicting coordinates are an input-contract error.

- [The vocabulary lint: what is banned, where, and how it fails](https://github.com/abdoupk/groundscan-analyzer-v2/issues/26): **two layers**, because each catches what the other misses - a **mechanical rule** over known terms, plus a **reviewed semantic category** catching synonyms. Measured: a ban list alone passes `metallic-like` -> `metal-like`, `cavity-like` -> `hollow-like`, `validated` -> `confirmed`, **none caught by a word list**. Scope is **`src/` and `tests/` only** - measured 0 hits there against 2,339 in `docs/legacy/` - or a whole-repo lint would be silenced to enforce nothing. **Hard gate with reasoned per-line suppression**: a lint with no escape hatch gets commented out.

- [The detection record](https://github.com/abdoupk/groundscan-analyzer-v2/issues/17): **five categories across three granularities** - run, scan and frame context, detection evidence, interpretive claims. A detection belongs to a **frame, not a scan**. **Evidence and claims are different kinds**: evidence carries method and provenance and needs no licence; a claim carries value + warrant + limitation and **a claim without its warrant is unrepresentable**. `not-emitted` and `indeterminate` are **discriminated result states on both kinds**, each with a reason code - one mechanism, because expressing "solidity absent" differently from "depth absent" would itself be a defect. **Depth is evidence only.**

- [The separation margin and stability criteria](https://github.com/abdoupk/groundscan-analyzer-v2/issues/28): margin, correlation, argmax stability and margin drift are **reported independently with no composite score**, and candidate ordering inside registration is **not a ranking**. Three **separate, decidable** checks produce `indeterminate`, each against a **recorded protocol** rather than a fixed constant, so the magnitude is a live parameter. A passing check means the candidate is **well-defined and stable under that protocol, never that the alignment is physically real**. **No margin and no separation threshold** until an adequate corpus exists.

- [The order-dependence inventory and its tie rules](https://github.com/abdoupk/groundscan-analyzer-v2/issues/15): **four hazard classes**, fixed for this phase but **explicitly reopenable** - v2 is unbuilt, so a classification that cannot represent a real hazard is wrong. **Order** is closed by canonical ordering plus lattice-order numbering, with **padding excluded from component identity entirely**. **Tie** is decided by three checks; an exact dominance tie is `indeterminate` and an exact scale-estimator tie is a `scale_status` condition. The depth interval is **order-free by construction**. **Both corpus figures in the original table are withdrawn** - see [#38](https://github.com/abdoupk/groundscan-analyzer-v2/issues/38) - and the taxonomy is **amended** by [#32](https://github.com/abdoupk/groundscan-analyzer-v2/issues/32).

- [The perpendicular survey: a 90-degree turn, two scans, one answer](https://github.com/abdoupk/groundscan-analyzer-v2/issues/10): **the result is a frame relation, not a fusion** - no cells merged or resampled, and **no cross-scan count or density is ever produced**, because **an interpolated value is padding by definition**, so a merged grid would not be a measurement grid. The relation is carried as **composed classes in Z/4**, so a cycle is either **closed or contradictory, never merely implausible**; no transform matrix is ever an assertion. The **canonical position is the exact integer lattice index**; a shared-frame position is derived, may be **fractional**, and is then **not a homogeneous unit pair**.

- [The input contract: a name-based reading of a user-configurable export](https://github.com/abdoupk/groundscan-analyzer-v2/issues/23): a **closed column registry matched by name**, never by position, and **the unit is part of the name** - `Impulse X [ft]` is an unknown column, never a convertible variant. **No alias table** until OKM shows a real one. **Reordering is not a variation at all**, so the silent-mis-read hazard is impossible rather than handled. The metric columns are a **derived echo**: the engine recomputes the expected series under `metric-coordinate-v1` at a tolerance **derived from the declared precision** and **never replaces the vendor values**, which makes the all-zero trap **decidable**.

- [What happens to latitude and longitude?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/5): **registered, but only the presence state is kept** - absent, present-but-empty, present-with-value - and the **values are discarded** from the record and the canonical payload. The deciding fact is that the export **declares no datum at all**, so by the glossary's own rule these are **unframed values**: numbers wearing a position's grammar. All nine files carry them **present-but-empty**. Discarding the value is also what keeps the canonicalisation ruling intact, since metadata is excluded by design.

- [Which quality signals are defensible physics, and which are policy?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/7): the ruling is a **rule, not a case-by-case judgement** - *a threshold is retained only if the definition or computability of a **named quantity** requires it; if removing it merely changes whether a result is acceptable, ready, safe, strong or weak, it is consumer policy and is deleted.* Applied across 13 field-quality, 15 operational and 7 screening thresholds and four weight dictionaries, it removes every policy number and keeps every real quantity. **Two refusals exist and physics has none** - a contract-valid scan is **always read**. **`not-emitted` means undefined, not insufficient.**

- [Zigzag acquisition and the artefacts it creates](https://github.com/abdoupk/groundscan-analyzer-v2/issues/14): **correction is declined entirely** - the engine reports the lattice exactly as exported and never infers within-line direction, and every alternative was **already blocked** by a prior decision, which is why it was never a judgement call. Measured by running legacy's own diagnostic on all nine exports: reversing odd lines makes adjacent-line correlation **worse**, with legacy's threshold firing for **none**, so it would have **damaged all nine**. Seven files give a decisive positive as-exported signal, **two are non-informative**, and **no file supports the accumulation-order hypothesis**.

- [Recurrence: eligibility, common level, tolerance, chance baseline, correspondence](https://github.com/abdoupk/groundscan-analyzer-v2/issues/27): **recurrence is not licensed for the supported source**, because comparability is unrecoverable - the `Apply Active Modifiers` flag transforms values with **no trace in the file** - and since the licence was conditional, **the condition failing is the licence working as designed**. **Correction to the ticket's own framing**: per-file offsets spanning 32 to 131,772 are **not** a reason, since background subtraction cancels a constant offset. Verified on the corpus instead: **six of nine exports are 100% integral**, and the two exports of the only repeat pair sit on **opposite sides** of the divide.

- [What does the origin of a scan mean, physically?](https://github.com/abdoupk/groundscan-analyzer-v2/issues/8): **the origin is real, recorded nowhere, and unverifiable**, and the engine's job is to say exactly that. - **Whether the validation apparatus is rebuilt in this effort or a following one.** The epistemic regime is decided here; the size of the apparatus that enforces it is not. The regime does, however, fix two things that apparatus must do: enforce a **banned-claim-form check** so no `metallic-like` or field-validated phrasing can enter the contract, and enforce the **stale-limitation test**. The record ruling adds a third that is mechanical rather than procedural: the **closed vocabulary** must hold across fields, enums, limitation strings, and error messages. [The metamorphic properties](https://github.com/abdoupk/groundscan-analyzer-v2/issues/30) add two more, and the second is the one that would be missed: the **closed transform vocabulary** must be enforced alongside the closed claim vocabulary, and a property whose **preconditions no longer hold must fail** - structurally identical to the stale-limitation test, applied to promises rather than to claims. [The vendor compatibility gate](https://github.com/abdoupk/groundscan-analyzer-v2/issues/18) adds a fourth: **each definitional bound needs an independent validation test** - bound validity, witness attainment, production agreement - with an oracle **independent of the implementation**, since one sharing production's code verifies nothing. Still fog: a handoff boundary, not a design question. [Which independent oracles](https://github.com/abdoupk/groundscan-analyzer-v2/issues/34) has now settled **three things inside that boundary**, which narrows what is left: an oracle is **independent by construction** where a bound is derived from an inventory rather than computed twice, so the fourth obligation above is satisfied by derivation and not by a second implementation; **measured agreement never justifies a grade**, so the corpus partition is evidence and not a property; and a **bumped convention is an explicit transform** in the property registry, which is the **fifth** enforcement obligation - **governed and excluded outputs**, with the exclusion argued structurally from the shared `h(1/2)` rather than measured.
- **An adequate evaluation corpus for the separation criterion.** Named now as a named gap rather than a fog patch, because it is the single thing standing between a provisional criterion and a real one. It requires **independent real repeat acquisitions** - two operators or two passes over genuinely the same ground, with no relationship known in advance. The corpus has none: the nine files are separate vendor demo scans, and the one genuine pair correlates at 0.7678 where constructed repeats reach 0.9998, so it cannot stand in. Until such data exists, `indeterminate: criteria-not-established` remains correct for close cases and the separation criterion stays provisional.
- **Cross-acquisition stability validation.** Self-alignment stability is measured; whether the argmax check is valid when aligning two *independent* acquisitions of one area is not. Same underlying cause as the corpus gap above - the same missing real repeat data would settle both.
- **Whether a stable reference is a defensible *response* claim** - a recurring claim about the measurement rather than the ground, and a possible answer to a product with no field truth. Named in the characterisation licensing ticket; sharp enough to be a ticket only once that ticket establishes whether a defensible source is reachable at all.

## Out of scope

Work ruled beyond the destination. Never graduates; returns only if the destination is redrawn, and then as a fresh effort.

- **Reporting, report generation, viewer, visualisation, plotting, TUI.** Explicitly excluded from v2 scope. May later exist as external consumers of the engine's structured results; the engine must not be shaped to serve them.
- **Device-specific adapters, plugins, or a device framework.** The common CSV contract is a product requirement. Revisit only if evidence proves it insufficient.
- **Geodetic science of any kind** - GPS, UTM, EPSG, WGS84, datum transformations, compass/bearing conversion, and any use of latitude/longitude in the engine's mathematics.
- **Preserving legacy code, helpers, abstractions, models, dependencies, comments, docs, or tests for their own sake.** Clean greenfield rebuild.
- **Historical version numbers, release names, milestone terminology, stale compatibility notes, old branch names, and historical implementation labels** in v2 source, docstrings, comments, or current documentation.
- **Prescribing a project structure or architecture.** No clean/hexagonal/DDD/services-repositories, no folder or package layout, decided on this map. The architecture is derived from the decisions this map makes; it is an output, not a ticket here.
- **Implementation tickets.** This map produces decisions, not build slices.
- **Acquiring independent field ground truth.** None is available. This is a recorded constraint on the epistemic regime, not work for this map.
